# terminal_mux + Metal host — hardening plan

Source: a review of the Zig core (`terminal_mux`, parser → grid/scrollback →
panes/PTY → C ABI) and its Swift GPU host (`aiconductor/Terminal/MetalTerminalView`).
Both codebases are in good shape; this is hardening, not rescue.

Baseline recorded by the reviewer, worth re-confirming before you start:
`zig build test` gives **119/125**, and all 6 failures are `OpenptyFailed` from a
sandbox that denies PTY allocation — environmental, not regressions. If you see
a different failure count, stop and say so rather than working around it.

The plan is settled. Work it in the order below, one item at a time: make the
change, run the check, report. Do not redesign the list.

---

## Pass 1 — the three that pair up (do these together)

These are one story: the emulator gains a way to answer, the PTY gains a bound,
and the host learns when the child is gone.

### Z1 · Query responses (DA / DSR / CPR) — Zig
`handleCsi` has no case for `'n'` or `'c'`. Vim, fzf, inner tmux and most TUI
libraries send `ESC[6n` and `ESC[c` and then **wait**, so they stall to timeout
or drop into degraded modes.

Add a bounded response queue to the emulator (`resp_pending`, ~64 bytes),
drained across the C ABI as `tmux_take_responses`, written back to the PTY by
the host — the host owns `sendInput`, so the emulator must not write directly.

- DA1 → `ESC[?62;22c`
- DA2 → `ESC[>0;277;0c`
- DSR-CPR `ESC[6n` → `ESC[{row+1};{col+1}R`, cursor clamped into origin mode
- OSC 10/11 `?` → answer from the active theme

Test: feed `ESC[6n`, assert the queue holds the CPR with origin-mode clamping.

### Z3 · `Pty.write` must not block forever — Zig
On `EAGAIN` it polls 1000ms and retries without bound. A large paste into a
child that isn't reading (Ctrl-Z'd, slow, dead-but-unreaped) hangs the caller —
and via `tmux_paste` that caller is **the Swift main thread**.

Give `write` a total budget (~250ms of EAGAIN waiting), return the partial
count, and make `tmux_paste` report bytes actually written.

### Z4 · Notice the child died — Zig
`tmux_is_alive` exists and nothing watches it. In `tmux_drain`, when a pane's
`readOutput` returns 0 (EOF) or poll shows `POLLHUP`, check `isAlive()` and set
a per-session `child_exited` flag, read-and-clear via `tmux_take_exit`.

### S1 · Dead shell = frozen pane — Swift
`MetalTerminalView` never checks liveness, so an exited child leaves the last
grid on screen with no indication. In a cockpit hosting agent panes all day, a
dead pane is indistinguishable from an idle agent. (SwiftTerm already prints
`[process exited (n)]`; the Metal path does not.)

On each `ptySources` wake, after `tmux_drain`, consume `tmux_take_exit`; when
exited, draw a `[process exited]` bar as a compositor row (not PTY text), stop
the DispatchSources, and `AXAnnounce.post`.

### S3 · Large paste can freeze the UI — Swift
`paste()` → `tmux_paste` → the unbounded EAGAIN loop, all on main. The existing
comment claims `tmux_paste` "chunks big input" — **it does not; the comment
lies**. Fix the comment first, then chunk in Swift (~8KB slices) so bracketed
paste behaves too, and dispatch pastes over ~64KB off-main.

### S2 · Boot-command race in the SwiftTerm fallback — Swift
`SwiftTermTerminal.init` calls `send(txt:)` straight after `startProcess` —
exactly the race `MetalTerminalView.spawnSession` documents and already fixes.
zsh's `tcsetattr(TCSAFLUSH)` discards pre-init input, so a staged `claude` line
half-survives or vanishes.

Port the quiescence debounce (first output → 250ms quiet → type, 2s fallback).
`scheduleBootAfterQuiescence` transplants directly.

## Pass 2 — compat batch

### Z2 · Colon-form SGR is dropped entirely
The parser's `in_subparam` skip (added so subparams stop corrupting top-level
params) means `38:2::r:g:b` collects only `params[0]=38`; `handleSgr` then finds
no `5`/`2` follower and applies **no colour at all**. Colon-form truecolor is
what kitty/foot-style apps increasingly emit.

Capture subparams properly (`subparams: [MAX_PARAMS][4]u16` + `sub_count`,
capped) and teach 38/48 to accept both `38;2;r;g;b` and `38:2:r:g:b`. Treat
`4:3` (curly underline) as plain underline. Parser tests for both forms.

### Z5 · Alt-screen modes 47 and 1047
Only 1049 is handled, so legacy apps draw over the primary grid.
`47h/l` → plain swap, no cursor save. `1047h` → clear alt, then swap.
`1047l` → swap back, then clear alt.

### Z6 · `tmux_split` ignores the session's shell
It always spawns `$SHELL` even when `tmux_create` was given an explicit one, so
splitting a custom-shell session silently changes shell. Store the spawn shell
on the `Session` and reuse it in `tmux_split` / `tmux_new_window`.

## Pass 3 — cwd, end to end

### Z7 · Parse OSC 7
`pane.cwd` is dead weight today. Parse OSC 7 into `terminal.cwd_pending` (same
shape as bell/clipboard) and expose `tmux_pane_cwd`.

### S4 · `copyWorkingDirectory` pastes the window title
The comment says it falls back to the title "if it looks like a path" and there
is no such check — copy while the title is `vim — server.rs` and that is what
lands on the pasteboard. Consume `tmux_pane_cwd`; until Z7 lands, at minimum
require the title to start with `/` or `~` and disable the menu item otherwise.

### Z8 · OSC 52 truncates silently at 4096 bytes
Larger payloads cut mid-base64, the Swift decode fails, and the copy is
**silently dropped**. Grow the buffer (~100KB covers real use) or chunk via a
`tmux_take_clipboard` continuation. Once Z1's response channel exists, answer
OSC 52 `?` with a refusal rather than silence.

## Pass 4 — the perf move (measure before and after)

### S5 · Sustained output loads main twice
PTY drain+parse runs on `.main`, then `draw(in:)` recomposes the whole grid on
main again. Move `tmux_drain` to one serial background queue per view (the ABI
documents per-session single-thread driving, which one queue satisfies), keep a
`dirty` flag, hop to main only to set `needsDisplay`. Fold the URL scan and
codepoint snapshot into that same drain pass so `draw` becomes pure
compose-and-upload.

Use the existing PerfLog spans (`terminal.draw.slow` >8ms,
`findUrls.slow` >4ms) and report the numbers before and after. If they do not
improve, say so and leave it reverted — this one is justified by measurement or
not at all.

## Pass 5 — polish, only if the above is done and green

- **S6** Multi-row URLs: the highlight loop skips spans >1 row, `urlRange(at:)`
  accepts any span, so a 3-row URL is clickable but drawn plain. Unify — prefer
  both supporting multi-row.
- **Z9** `insertChar` off-by-one at the final column (`cols - start_col - 1`
  blanks nothing; xterm blanks the cell). One line plus a test.
- **Z10** Missing `CSI Z` (CBT), `CSI b` (REP), DECALN, mode 1005. CBT matters
  most — readline apps use it.
- **Z11** `isZeroWidth` lacks Thai, Devanagari, Myanmar and most combining
  blocks, so those scripts advance the cursor per mark. Extend from Unicode
  `Mn`/`Me` categories rather than by hand.
- **S7** IME caret rect ignores `scrollback_offset`; while scrolled back the
  candidate window anchors at the hidden live cursor. Clamp to the viewport.
- **S8** Accessibility: one `staticText` holding the whole screen gives
  VoiceOver no line navigation. Expose `accessibilityChildren` as row elements —
  the grid is already row-addressable in `chars`.
- **S9** `EmbeddedTerminalView` falls back Metal→SwiftTerm silently; surface
  which engine actually rendered, in the context menu or tooltip.
- **Z12** Delete the dead `RingBuffer` generic (superseded by `Scrollback`) or
  use it — it is tested but unreferenced.
- **Z13** `tmux_sync_suppressed` mutates state from what reads as a getter on
  the render path. Move the self-heal into `tmux_drain`.
- **S10** The sync-suppressed retry schedules `needsDisplay` every runloop turn
  for up to 250ms. Coalesce to one 30ms timer restart.

## Build hygiene — do this first, it protects everything else

**Staleness check.** The app links `libterminal_mux.a` by relative path. The
`.a` currently *is* newer than the sources, but nothing enforces that, and this
fleet has already been bitten by a stale static library. Add an Xcode pre-build
script (or a documented `make` rule) that re-runs `zig build` when
`terminal_mux/src/**` is newer than `zig-out/lib/libterminal_mux.a`.

**Sandbox-skippable PTY tests.** The 6 PTY tests cannot run where `/dev/ptmx`
is denied. They already catch-and-skip two error codes; add the sandbox's
`OpenptyFailed` path so `zig build test` is green everywhere an agent runs it.
Do this early — you will want a green baseline to work against.
